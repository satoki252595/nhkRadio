# Playback 1.0.0 (7): 再生終了・進捗の回帰修正

作業記録: [Issue #14](https://github.com/satoki252595/nhkRadio/issues/14)。

## ビルド6の実機検証で再現した問題

iPhone 16e / iOS 27.0.1 のTestFlight 1.0.0 (6)で、音声を最後まで聴いた後に再生すると、操作表示だけが再生中になり、末尾から進まないことを確認した。

また、キューの差替えが旧音源の進捗保存より先に行われていた。同じインデックスにある新しい音源へ、旧音源の再生位置と長さが書き込まれ、続きからの再生に影響する。

## 修正

- キュー変更前に旧音源の進捗を保存し、キュー内からの選択も同じ処理を使う。
- 終了済みの音源は共通の再開処理で先頭から再生し直す。
- 保存済みの位置を読み込み時に固定し、実際の音源の長さを超えている場合は先頭から再生する。
- 遅れて届いたシーク完了・終了通知が別の音源へ反映されることを防ぎ、周期通知では現在のAVPlayerの時刻を読む。
- ダウンロード再開情報の定数に正しいactor境界を指定し、既存のコンパイラ警告を解消する。

## 提出前の自動検証

追加した3件は修正前にすべて失敗し、修正後は3件とも合格した。iOS Simulator 26.5で全30件合格・スキップ0件。実際の録音2件について、端末内ファイルのPCMデコードとNotionのHTTPS配信をPlayerEngineで再生し、時間が進むことも確認した。録音や期限付きURLはGit外のテストキャッシュだけに置き、テスト後に取り除く。

Pythonは84件合格。OAuth Workerの型検査も合格。詳細なログ・xcresult・バイナリ・実機動画はGit外の公開証跡に保持する。

これはビルド7の自動検証結果であり、TestFlight実機検証の代わりにはしない。ビルド6の実機音声・動画・削除後再生の結果や動画は、ビルド7の提出証拠として流用しない。

## ダウンロード表示の即時更新（ビルド8）

実機のビルド7で、音源の保存を削除するとダウンロード一覧からは消える一方、開いたプレイヤーの保存ボタンとライブラリの保存済みバッジがタブ切替まで残ることを確認。SwiftDataの単発fetchはレコードの追加・削除をViewへ通知しないため、共通の`downloadRecord(forKey:)`で保存レコードの変更をObservationへ登録し、保存完了・単体削除・全削除から通知する。ライブラリ、保存済みフィルタ、履歴、詳細、プレイヤーの全呼出元へ適用される。

回帰検証は`testDownloadRecordReadsObserveCompletionAndBothDeletionPaths`。Viewと同じObservation読み取りを登録し、保存完了と単体/全体削除でそれぞれ通知され、レコード取得結果も切り替わることを確認する。
