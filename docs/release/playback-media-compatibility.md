# 音源のCannot Openと対応形式

2026-10-20、Issue #14。ユーザーからNHKラジオ録音の音源がCannot Openになる画面と、対応拡張子の案内を求められた。

## 原因と対応

実際の「名演奏ライブラリー」の添付は拡張子とContent-TypeがM4A/audio/mp4だが、内部はID3タグ付きADTS HE-AACだった。録音処理はyt-dlpが生成したAACをM4Aへ改名しており、コンテナの変換をしていなかった。Apple標準APIで同じファイルの読み込み失敗を再現し、正しいMIME型を指定した場合の読み込み成功を確認した。別の実録音は正しいM4Aコンテナだったため、全ファイルをAACと決めつけない。

アプリは音声の先頭最大64 KiBを読み、ID3タグの長さを検証してAAC/MP3などの実形式を判別する。Appleの公開API `AVURLAssetOverrideMIMETypeKey`（最低対応iOS17で利用可能）で正しい型を指定し、直接再生と保存済みファイルの両方に適用する。先頭取得はキャッシュを無効にし、期限切れURLの古い部分応答を再利用しない。範囲要求を無視する配信元でも読み取る量を制限してタスクをキャンセルする。64 KiBを超えるID3タグは標準パーサーに委ねる。

録音側はADTS AACをFFmpegで再圧縮せず実際のM4Aコンテナへ変換する。失敗時の不完全なM4Aを残さず、誤ったaudio/mp4ファイルを今後生成しない。このコード変更の運用反映状況は別途確認する。

関連する不具合も共通経路で修正した。

- DB切り替え後の履歴・キュー・ダウンロードは、音源自身のDBの保存済み列設定を使う。
- 添付の名前が変わった・削除された場合、別の先頭ファイルで代用しない。更新を案内する。
- 未対応形式、取得時のHTTPエラー、通信障害、形式や破損の問題を区別して日本語で案内する。
- 再生対象の変更・停止時には、古いURL解決と形式確認のタスクをキャンセルする。

## 対応形式

「設定」→「対応ファイル形式」に、実行中のiOSが読み込み対象として返す拡張子とアプリの対象形式との共通部分を表示する。拡張子だけで内部コーデックの再生を保証しない。DRM、破損、内部形式の制約も画面に記載する。

iOS26.5 Simulatorで返された一覧は音声 `.m4a .mp3 .aac .wav .aif .aiff .flac .caf .ogg .opus`、動画 `.mp4 .mov .m4v`。WebM/MKVはこの環境の一覧に含まれず、再生を試す前に対応外と案内する。端末・OSで一覧が変わるため、全OS共通の固定保証として扱わない。

## 検証と公開

- 合成AACに誤ったM4A名とID3タグを付け、修正後に実際のPCMサンプルが得られる回帰テストを追加。
- 実録音2件（正しいM4A、M4Aと誤記されたADTS HE-AAC）について、iOS Simulatorで保存ファイルのPCMデコードと直接再生の時間進行を確認。生の録音と期限付きURLはGit外のみ。CIでは私的サンプルがなければこの追加検証だけをskipする。
- DBを跨ぐ元の列参照と、削除された添付を別ファイルで代用しないことをテスト。
- 録音側は実際のFFmpegでAAC→M4Aのコンテナ変換と失敗時の不完全ファイル削除をテスト。
- 提出候補は1.0.0 (6)。最終commitの全チェック、source/binaryゲート、TestFlight6の実機・新しい動画・completeゲートを別途記録し、旧ビルドの証跡を流用しない。審査提出は本人の最終確認後。

Appleの仕様（確認日2026-10-20）: [形式指定キー](https://developer.apple.com/documentation/avfoundation/avurlassetoverridemimetypekey)、[端末の対応型一覧](https://developer.apple.com/documentation/avfoundation/avurlasset/audiovisualcontenttypes)。
