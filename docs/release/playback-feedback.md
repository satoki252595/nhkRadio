# 再生・ダウンロードの状態表示

2026-10-20、Issue #14。ユーザーから「ダウンロード中で再生できない場合は理由を表示し、類似するUI/UXの問題も直す」と依頼。

ビルド5では、URL取得後もAVPlayerの読み込み待ちと失敗を監視する。ダウンロードと再生は並行できるため、一律に再生を禁止しない。両方が待機している場合はダウンロード進捗と読み込み待ちの説明、再試行、ダウンロードを中止して再生する操作を表示する。ミニプレイヤーにも状態を表示する。

関連する修正:

- 再生準備中に一時停止した場合は、URL取得後に勝手に再生しない。
- 新しい曲の準備開始時に古い曲を止め、取得失敗時に古い曲を再生中と誤表示しない。
- URL取得失敗・AVPlayerのファイル読み込み失敗・音声セッション開始失敗を通知する。失敗後の再生ボタンから再取得できる。
- ダウンロードのURL取得中に中止した場合は、取得が後から完了しても保存を開始しない。古いタスクの通知で新しい進捗や保存状態を上書きしない。
- HTTPエラーの応答を保存済みメディアとして登録しない。保存先作成の失敗も通知する。
- ダウンロード画面に保存完了前のオフライン再生の制約を記載する。ライブラリにはダウンロード中のバッジ、VoiceOverには進捗を表示する。
- プレイヤーを開いたままでもダウンロード失敗を表示し、保存し直す操作を案内する。次の曲がないボタンや、時間が未取得のスキップ操作は無効にする。

既存のXCTestに、待機表示と中止、準備中の一時停止、失敗からの再試行、実際のAVPlayerのファイル読み込み失敗を確認する4件を追加した。最終commitの検査とTestFlight実機確認・審査動画は別途、Git外の公開証跡へ保存する。ビルド3の検証や動画をビルド5の証拠に流用しない。

アプリ再起動時はメモリ内のタスク一覧の復元より先に完了通知が届くことがある。保存したリクエストIDで通知を照合し、復元前の完了も保存へ反映する。同じファイルの再試行には新しいIDを使い、中止した試行の遅延通知を無視する。旧バージョンのダウンロード情報との互換性も回帰テストで確認する。ビルド4はこの監査で差し替え、審査へ提出しない。
